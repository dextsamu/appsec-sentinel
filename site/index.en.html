Why they exist

A typical report says "all good". This one says how much it looked at.

Whoever sets budget and priorities trusts what the report says was tested. Claiming a test that never ran is worse than not testing.

The two skills

Security and privacy, one method

Each works on its own. Together they share the audit folder and produce a single PDF report.

The method

Authorization first, then the work

No active test starts without a scope and written confirmation. Which phases run depends on the mode: quick, standard or full.

  1. Intake and authorization gateOwnership, authorized environments, permitted tests, limits and the person responsible for the kill switch. Without confirmation: local analysis only.
  2. InventoryFiles, routes, roles, data, environments; endpoint matrix.
  3. Threat modelFlows, trust boundaries, STRIDE and LINDDUN, chained attack paths.
  4. Identity and authorizationSessions, MFA, OAuth, secrets, object and function access, tenants.
  5. Input, APIs, files, logicInjection, XSS, SSRF, CSRF, webhooks, business logic.
  6. Infrastructure and supply chainDatabase, cryptography, containers, CI/CD, SBOM, recovery.
  7. AI and automation if presentPrompt injection, RAG, tools and agents.
  8. Availability and cost only if authorizedApplication-level DoS and denial of wallet, with numeric limits and stop thresholds.
  9. PrivacyReal processing versus the privacy notice: handed to gdpr-sentinel.
  10. Validation and planFalse positives, refutation of high findings by an independent verifier, deduplication, retest, open questions for decision-makers.

Anatomy of a finding

Every finding also says how well it is proven

Pick a state: see what it means and what it takes to move up a level. Anonymized example.

HIGHDemo seed endpoint exempt from authentication, creates users with a fixed password
Stateconfirmed from code or configuration · medium confidence
EvidenceThe middleware lists the path among the public ones; the handler checks neither session, role nor token.
Expected / observedExpected: disabled in production or protected by role. Observed: reachable without authentication.
ImpactReal: not demonstrated, no test run. Potential: creation of accounts with a known password.
ImmediatelyBlock the path at the reverse proxy; check whether demo accounts exist in production.
RetestAnonymous request on staging: expect 401 or 404, no user created.
LimitsNot verified whether the route is in the production build.
RefutationA verifier other than the author tried to prove it wrong and did not manage to (outcome "resiste", i.e. holds).

The scripts are tested against fake apps and pages with known flaws, including a local instance and a page in the browser (tests/run_checks.py). This is not a benchmark on public vulnerable apps. Short English guide: README.en.md in each repository.

PDF report

A document you can hand to a client

Cover, index, owner summary, findings, documentary audit, coverage matrices, questions and action plan. Teal theme for security, amber for privacy. Click a page to enlarge it. The sample pages are from an Italian-language report.

Options: --sintetico for management, --lang en for English labels, --previous to compare with an earlier audit, --nis2 for an indicative mapping to the Art. 21 measures.

Installation

Ready in two minutes

  1. Download appsec-sentinel.skill and gdpr-sentinel.skill from the repositories' Releases.
  2. Upload them from the skills settings.
  3. Type /appsec-sentinel quick <repo>: it will ask about ownership, type of activity and mode before touching anything.
/plugin marketplace add dextsamu/appsec-sentinel
/plugin install appsec-sentinel@appsec-sentinel
/plugin install gdpr-sentinel@appsec-sentinel     # the twin skill, optional

As a plugin it updates with new releases. Or as a folder: git clone https://github.com/dextsamu/appsec-sentinel ~/.claude/skills/appsec-sentinel (for a single project into <project>/.claude/skills/). For the PDF report: pip install reportlab.

Antigravity: the project's .agents/skills/<skill-name>/ folder, or ~/.gemini/config/skills/ for all projects. Codex: a third-party source gives ~/.codex/skills/<skill-name>/, to be checked with codex --help.

Built for Claude, tried once each on Codex and Antigravity (Windows, quick mode, fake app, static analysis only). Paths, limits and the checks to run are in docs/ALTRI-AGENTI.md in the repository (Italian).

Limits

What they do not do

  • They do not find "all" vulnerabilities and do not certify security or compliance.
  • They do not replace a penetration tester, a DPO or a lawyer.
  • They run no tests on production or on unauthorized systems.
  • They do not change the product: they propose fixes to apply under a later mandate.
  • They do not run tools they lack: they prepare the commands for the client's environment.
  • They do not send secrets, personal data or private code to third-party services without authorization.
Responsible use. Use them only on your own systems or with the owner's written authorization: unauthorized access to a computer system can be a criminal offence. Reports contain sensitive details: keep them out of Git and public repositories.

Frequently asked questions

FAQ

Can I use them on a client's site?Only with the written authorization of the system owner. The skills run no active tests without a confirmed scope, but responsibility for their use stays with you.
Do the scripts replace scanners?No. The scanners stay yours: the skills import their output as "hypothesis to validate" candidates and handle rules, coverage, validation and the report.
Does "no findings" mean it is secure?No. Coverage only concerns what was inventoried and proven: the report says how much was really examined and how much remains unknown.
Is the draft processing register the Art. 30 register?No: it is a draft derived from the code, entirely "hypothesis to validate". Roles, legal bases, countries and retention periods are confirmed by the controller.
Do they work with other agents, not only Claude?They were tried once on Codex and once on Antigravity (Windows, quick mode, fake app, static analysis only): the rules were respected and the gaps that emerged were fixed. This is not a guarantee of compatibility: the guide with install paths and limits is in docs/ALTRI-AGENTI.md in the repository (Italian).
Do I need both installed?No. They work separately. If both are installed, one hands work to the other and the report is a single one.
Where do the audit files go?In a confidential folder created outside the repository. Secrets never enter the reports: only location, type and shape are recorded.
